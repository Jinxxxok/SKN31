## ML 01_Numpy개요_배열생성

### Numpy

ML : 과거의 dataset을 가지고 패턴을 찾아 미래 예측

#### Numpy 데이터 구조
-   <b style='font-size:1.3em'>스칼라 (Scalar)</b>
    -   값 하나. (0차원)
-   <b style='font-size:1.3em'>벡터 (Vector)</b>
    -   여러개의 값들을 순서대로 모아놓은 데이터 모음(데이터 레코드)
    -   1D Tensor, 1D Array (1차원 배열)
-   <b style='font-size:1.3em'>행렬 (Matrix)</b>
    -   벡터들을 모아놓은 데이터 집합. 2개의 방향으로 값들이 관리된다.
    -   2D Tensor, 2D Array (2차원 배열)
-   <b style='font-size:1.3em'>텐서 (Tensor)</b>
    -   같은 크기의 행렬들(텐서들)을 모아놓은 데이터 집합. N개의 방향으로 값들이 관리된다.
    -   ND Tensor, ND Array (다차원 배열)

#### 용어
-   **축 (axis)**
    -   값들의 나열 방향
    -   하나의 축(axis)는 하나의 범주(분류, Category)이다.
-   **랭크 (rank)**
    -   데이터 집합에서 축의 개수.
    -   차원 (dimension) 이라고도 한다.
-   **형태/형상 (shape)**
    -   각 축(axis) 별 데이터의 개수
-   **크기 (size)**
    -   배열내 원소의 총 개수

### 넘파이 배열 (ndarray)

- numpy에서 제공하는 자료구조 N차원 배열 객체.
- 같은 타입의 값들만 가질 수 있다.
- 축(axis)별 데이터의 개수는 모두 동일하다.
- 빠르고 메모리를 효율적 사용 / 벡터 연산과 브로드캐스팅 기능 제공.

> <b style='font-size:1.5em'>차원 (dimension)</b>
>
> -   **Vector에서 차원**: 원소의 개수
> -   **넘파이 배열에서 차원**: 축의 개수

#### 내적 (Dot product)연산

ndarray: @연산자 제공
- 배열 @ 배열: 내적 계산 제공 @ << __matmul__ 메서드 사용

- 같은 인덱스의 원소끼리 곱한 뒤 결과를 모두 더한다.
- 벡터간의 내적의 결과는 스칼라가 된다.
- 조건
     * 두 벡터의 차원(원소의 개수)가 같아야 한다.
     * 앞은 행벡터 뒤는 열벡터이어야 한다. (numpy에서는 vector끼리 연산 시 자동 인식해 앞 행벡터 뒤 열벡터로 처리한다.)
    ```
     x = [1, 2, 3], y = [4, 5, 6]

     xTy = 1 * 4 + 2 * 5 + 3  * 6 = 32
     ```


    ```
    x1 = np.array([1, 2, 3, 4])
    y1 = np.array([10, 20, 30, 40])
    x2 = x1.reshape(2,2)
    y2 = y1.reshape(2,2)

    x2 @ y2
    =========================================
    array([[ 70, 100],
        [150, 220]])
    ```

## 데이터 전처리

### 결측치(Missing Value) 처리

#### 결측치 처리 방법

- ### 결측치 제거
    - 리스트와이즈 삭제(Listwise Deletion)
        * 결측치가 있는 행들을 삭제
        * 결측치가 많지 않을때 적합
    - 컬럼 삭제(Drop column)
        * 컬럼자체 결측치가 너무 많을경우 제거.
- ### 결측치 대체
    - 도메인 기반 처리
    - 평균 / 중앙값 / 최빈값 대체
    - 모델링 기반 대체
        - KNN 대체
    - 결측치를 표현하는 값(-1, '없음' 등)으로 대체

- ### 다중 대체
    - 여러 방식으로 결측치를 대체한 데이터셋을 만들어 분석 후 가장 좋은 데이터셋으로 ML 진행

## ROC Curve(Receiver Operating Characteristic Curve)와 ROC-AUC(Area Under the Curve) score


 **FPR(False Positive Rate-위양성율)**
    - 위양성율 (fall-out)
    - 1-특이도(TNR)
    - 실제 음성중 양성으로 잘못 예측 한 비율
    - 낮을 수록 좋다.
    - 재현율과 비례관계이다. (재현율이 올라가면 FPR(위양성률)도 같이올라감)
    - 허나 비례관계라고 하더라도
    $$
    \cfrac{FP}{TN+FP}
    $$
- **TPR(True Positive Rate-재현율/민감도)** 
    - 재현율(recall)
    - 실제 양성중 양성으로 맞게 예측한 비율
    - 높을 수록 좋다.
    $$
    \frac{TP}{FN+TP}
    $$
- Positive의 임계값을 변경할 경우 **FPR과 TPR(recall)은 비례해서 변화한다.**
- <b style='font-size:1.3em'>ROC Curve</b>
    - 이진 분류의 성능 평가 지표
    - Positive 확률을 이용해 class(0, 1)을 결정할 때 임계값이 변화에 따른 재현율(TPR)과 위양성율(FPR)의 변화를 이용해 모델의 성능을 평가한다.
        - FPR 변화할 때 TPR이 어떻게 변하는 지를 평가한다.
    - FPR을 X축, TPR을 Y축으로 놓고  놓고 임계값이 1 → 0 변화할때 두 값의 변화를 선그래프로 그린다.
    - Positive(양성), Negative(음성) 에 대한 모델의 성능의 강건함(robust)을 평가한다.

- **ROC-AUC Score**
    - ROC Curve의 결과를 점수화(수치화) 하는 함수로 ROC Curve 아래쪽 면적을 계산한다.
    - 0 ~ 1 사이 실수로 나오며 클수록 좋다.
        - AUC Score값이 크려면(1에 가까운 값) 임계값이 클 때 FPR은 작고, TPR의 값은 커야 한다. FPR이 작다는 것은 Negative 잘 분류했다는 것이고 TPR이 크다는 것은 Positive를 잘 분류 했다는 의미이므로 둘에 대한 분류성능이 좋다는 것을 의미한다.
   - **ROC-AUC 점수기준**
        - 1.0 ~ 0.9 : 아주 좋음
        - 0.9 ~ 0.8 : 좋음
        - 0.8 ~ 0.7 : 괜찮은 모델
        - 0.7 ~ 0.6 : 의미는 있으나 좋은 모델은 아님
        - 0.6 ~ 0.5 : 좋지 않은 모델

## 일반화 모델과 과적합 모델

### Generalization(일반화) 모델
- 일반적인 특성을 잘 학습한 상태

### 과대적합 & 과소적합 모델
#### 과대적합(Overfitting)
- 훈련데이터에 지나치게 맞춰 학습되어서 검증/테스트 데이터에서는 성능이 크게 낮아지는 모델(train set 학습 과도) or 데이터 전처리 과정에서 이상치로 인해 overfitting 발생
#### 과소적합(Underfitting)
- 훈련 데이터조차 제대로 학습하지 못한 모델 성능이 매우 낮아짐 훈련 데이터 / 검증,테스트 모두에서 성능이 낮다. (train set학습 부족)

### overfitting 원인
#### 학습 데이터 양에 비해 모델이 너무 복잡한 경우
- 데이터의 양을 늘린다 
    - 시간과 돈이 들기 때문에 어렵다.

- 모델을 좀 더 단순하게 만든다
    - 사용한 모델보다 좀 더 복잡도가 낮은 모델을 사용
    - 모델의 복잡도를 변경할 수 있는 규제와 관련된 하이퍼파라미터를 제공하는데 이것을 조절.

### Underfitting 원인
#### 데이터 양에 비해서 모델이 너무 단순한 경우
- 좀 더 복잡한 모델을 사용
- 모델이 제공하는 규제 하이퍼파라미터 조정.


ROC-AUC curve, precision_recall curve 차이점

ROC-AUC curve는 진음수를 확인하기 때문에 균형데이터에 적합하고
Precision_Recall curve는 양성(양수)만을 고려하기 때문에 불균형데이터에 적합

핵심 차이점은 TN(진음성)을 보냐 안보냐의 차이인데
ROC 곡선은 FPR(FP/(FP+PN))을 x축으로 두기때문에 TN(진음성)이 포함된다.
데이터가 균형이 잡혀있는 경우 TN이 풍부하기때문에 FPR제어가 잘되지만
음성이  99개고 양성이 1개인 불균형한 데이터를 사용했을경우
ROC-AUC curve는 좋아보이는 착시효과만 생기지만 PR은 진짜 성능을 그대로 드러낸다.

대략적인 데이터 균형에서는 -> ROC-AUC curve
양성이 드문 경우(사기 탐지, 희귀 질환, 이상 탐지 등) -> Precision_Recall curve

환자 200명을 암진단을 했을때 (암 100명/정상 100명)이라는 가정하에
	      실제: 암  실제: 정상
예측: 암	TP = 85	FP = 10
예측: 정상	FN = 15	TN = 90

ROC-AUC가 보는 FPR은 FP / FP+PN = 10/100 = 10% TN(90)이 분모에 있어서 통제가 잘 된다.
PR(Precision_Recall)이 보는 Precision TP/TP+FP = 85/(85+10) = 89% 진음수를 사용하지 않아서 양성예측의 정확도만 본다.

희귀 사기 탐지, 거래 10,000건 (사기100건 / 정상 9900건)
사기(양성), 정상(음성)

ROC-AUC가 보는 FPR = 0/(0+9900) 사기를 하나도 못잡는데 FPR 0% 
PR이 보는 Precision & Recall Recall 0% (TP/(TP+FN) = 0/(0+100)) TN을 안 봐서 속지 않음. 사기를 하나도 못 잡는다는 게 그대로 드러남
PR 곡선은 TN을 전혀 사용하지 않는다. Precision과 Recall 모두 양성(사기)에만 집중하기 때문에, 
TN이 아무리 많아도 점수에 영향을 주지 않습니다. 그래서 불균형 데이터에서 진짜 탐지 성능이 고스란히 드러납니다.

TN = (올바른 음성) 정상 -> 정상 예측
FP = (오경보) 정상 -> 양성 예측

FPR = 실제로 정상인 사람들 중에서, 모델이 잘못 "위험하다"고 경보를 울린 비율

FPR <===> Specificity(특이도: 정상인을 정상이라 맞힌 비율) 항상 반비례 FPR+Specificity = 1

ROC X축 FPR(오경보율) Y축 TPR(재현율)

정면에서 찍으면 → 가장 많은 정보 담김 ✅

PCA는 **"어느 각도에서 찍어야 가장 많은 정보가 담기는가"**를 자동으로 찾아줘요.

PCA 동작 원리

        ↓
3️⃣ PC1과 직각인 방향 중 분산 최대 → PC2 (2번 주성분)
        ↓
4️⃣ 원하는 차원만큼 주성분 선택
        ↓
저차원 데이터 (압축됨)
