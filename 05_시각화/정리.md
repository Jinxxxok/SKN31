## ML 01_Numpy개요_배열생성

### Numpy

ML : 과거의 dataset을 가지고 패턴을 찾아 미래 예측

#### Numpy 데이터 구조
-   <b style='font-size:1.3em'>스칼라 (Scalar)</b>
    -   값 하나. (0차원)
-   <b style='font-size:1.3em'>벡터 (Vector)</b>
    -   여러개의 값들을 순서대로 모아놓은 데이터 모음(데이터 레코드)
    -   1D Tensor, 1D Array (1차원 배열)
-   <b style='font-size:1.3em'>행렬 (Matrix)</b>
    -   벡터들을 모아놓은 데이터 집합. 2개의 방향으로 값들이 관리된다.
    -   2D Tensor, 2D Array (2차원 배열)
-   <b style='font-size:1.3em'>텐서 (Tensor)</b>
    -   같은 크기의 행렬들(텐서들)을 모아놓은 데이터 집합. N개의 방향으로 값들이 관리된다.
    -   ND Tensor, ND Array (다차원 배열)

#### 용어
-   **축 (axis)**
    -   값들의 나열 방향
    -   하나의 축(axis)는 하나의 범주(분류, Category)이다.
-   **랭크 (rank)**
    -   데이터 집합에서 축의 개수.
    -   차원 (dimension) 이라고도 한다.
-   **형태/형상 (shape)**
    -   각 축(axis) 별 데이터의 개수
-   **크기 (size)**
    -   배열내 원소의 총 개수

### 넘파이 배열 (ndarray)

- 축(axis)별 데이터의 개수는 모두 동일하다.
- 빠르고 메모리를 효율적 사용 / 벡터 연산과 브로드캐스팅 기능 제공.

> <b style='font-size:1.5em'>차원 (dimension)</b>
>
> -   **Vector에서 차원**: 원소의 개수
> -   **넘파이 배열에서 차원**: 축의 개수

#### 내적 (Dot product)연산

ndarray: @연산자 제공
- 배열 @ 배열: 내적 계산 제공 @ << __matmul__ 메서드 사용

- 같은 인덱스의 원소끼리 곱한 뒤 결과를 모두 더한다.
- 벡터간의 내적의 결과는 스칼라가 된다.
- 조건
     * 두 벡터의 차원(원소의 개수)가 같아야 한다.
     * 앞은 행벡터 뒤는 열벡터이어야 한다. (numpy에서는 vector끼리 연산 시 자동 인식해 앞 행벡터 뒤 열벡터로 처리한다.)
    ```
     x = [1, 2, 3], y = [4, 5, 6]

     xTy = 1 * 4 + 2 * 5 + 3  * 6 = 32
     ```


    ```
    x1 = np.array([1, 2, 3, 4])
    y1 = np.array([10, 20, 30, 40])
    x2 = x1.reshape(2,2)
    y2 = y1.reshape(2,2)

    x2 @ y2
    =========================================
    array([[ 70, 100],
        [150, 220]])
    ```

## 데이터 전처리

### 결측치(Missing Value) 처리

#### 결측치 처리 방법

- ### 결측치 제거
    - 리스트와이즈 삭제(Listwise Deletion)
        * 결측치가 있는 행들을 삭제
        * 결측치가 많지 않을때 적합
    - 컬럼 삭제(Drop column)
        * 컬럼자체 결측치가 너무 많을경우 제거.
- ### 결측치 대체
    - 도메인 기반 처리
    - 평균 / 중앙값 / 최빈값 대체
    - 모델링 기반 대체
        - KNN 대체
    - 결측치를 표현하는 값(-1, '없음' 등)으로 대체

- ### 다중 대체
    - 여러 방식으로 결측치를 대체한 데이터셋을 만들어 분석 후 가장 좋은 데이터셋으로 ML 진행

## ROC Curve(Receiver Operating Characteristic Curve)와 ROC-AUC(Area Under the Curve) score


 **FPR(False Positive Rate-위양성율)**
    - 위양성율 (fall-out)
    - 1-특이도(TNR)
    - 실제 음성중 양성으로 잘못 예측 한 비율
    - 낮을 수록 좋다.
    - 재현율과 비례관계이다. (재현율이 올라가면 FPR(위양성률)도 같이올라감)
    - 허나 비례관계라고 하더라도
    $$
    \cfrac{FP}{TN+FP}
    $$
- **TPR(True Positive Rate-재현율/민감도)** 
    - 재현율(recall)
    - 실제 양성중 양성으로 맞게 예측한 비율
    - 높을 수록 좋다.
    $$
    \frac{TP}{FN+TP}
    $$
- Positive의 임계값을 변경할 경우 **FPR과 TPR(recall)은 비례해서 변화한다.**
- <b style='font-size:1.3em'>ROC Curve</b>
    - 이진 분류의 성능 평가 지표
    - Positive 확률을 이용해 class(0, 1)을 결정할 때 임계값이 변화에 따른 재현율(TPR)과 위양성율(FPR)의 변화를 이용해 모델의 성능을 평가한다.
        - FPR 변화할 때 TPR이 어떻게 변하는 지를 평가한다.
    - FPR을 X축, TPR을 Y축으로 놓고  놓고 임계값이 1 → 0 변화할때 두 값의 변화를 선그래프로 그린다.
    - Positive(양성), Negative(음성) 에 대한 모델의 성능의 강건함(robust)을 평가한다.

- **ROC-AUC Score**
    - ROC Curve의 결과를 점수화(수치화) 하는 함수로 ROC Curve 아래쪽 면적을 계산한다.
    - 0 ~ 1 사이 실수로 나오며 클수록 좋다.
        - AUC Score값이 크려면(1에 가까운 값) 임계값이 클 때 FPR은 작고, TPR의 값은 커야 한다. FPR이 작다는 것은 Negative 잘 분류했다는 것이고 TPR이 크다는 것은 Positive를 잘 분류 했다는 의미이므로 둘에 대한 분류성능이 좋다는 것을 의미한다.
   - **ROC-AUC 점수기준**
        - 1.0 ~ 0.9 : 아주 좋음
        - 0.9 ~ 0.8 : 좋음
        - 0.8 ~ 0.7 : 괜찮은 모델
        - 0.7 ~ 0.6 : 의미는 있으나 좋은 모델은 아님
        - 0.6 ~ 0.5 : 좋지 않은 모델

#### 과대적합(Overfitting)
- 훈련데이터에 지나치게 맞춰 학습되어서 검증/테스트 데이터에서는 성능이 크게 낮아지는 모델(train set 학습 과도) or 데이터 전처리 과정에서 이상치로 인해 overfitting 발생
#### 과소적합(Underfitting)
- 훈련 데이터조차 제대로 학습하지 못한 모델 성능이 매우 낮아짐 훈련 데이터 / 검증,테스트 모두에서 성능이 낮다. (train set학습 부족)

### overfitting 원인
#### 학습 데이터 양에 비해 모델이 너무 복잡한 경우
- 데이터의 양을 늘린다 
    - 시간과 돈이 들기 때문에 어렵다.

- 모델을 좀 더 단순하게 만든다
    - 사용한 모델보다 좀 더 복잡도가 낮은 모델을 사용
    - 모델의 복잡도를 변경할 수 있는 규제와 관련된 하이퍼파라미터를 제공하는데 이것을 조절.

### Underfitting 원인
#### 데이터 양에 비해서 모델이 너무 단순한 경우
- 좀 더 복잡한 모델을 사용
- 모델이 제공하는 규제 하이퍼파라미터 조정.


ROC-AUC curve, precision_recall curve 차이점

ROC-AUC curve는 진음수를 확인하기 때문에 균형데이터에 적합하고
Precision_Recall curve는 양성(양수)만을 고려하기 때문에 불균형데이터에 적합

핵심 차이점은 TN(진음성)을 보냐 안보냐의 차이인데
ROC 곡선은 FPR(FP/(FP+PN))을 x축으로 두기때문에 TN(진음성)이 포함된다.
데이터가 균형이 잡혀있는 경우 TN이 풍부하기때문에 FPR제어가 잘되지만
음성이  99개고 양성이 1개인 불균형한 데이터를 사용했을경우
ROC-AUC curve는 좋아보이는 착시효과만 생기지만 PR은 진짜 성능을 그대로 드러낸다.

대략적인 데이터 균형에서는 -> ROC-AUC curve
양성이 드문 경우(사기 탐지, 희귀 질환, 이상 탐지 등) -> Precision_Recall curve

환자 200명을 암진단을 했을때 (암 100명/정상 100명)이라는 가정하에
	      실제: 암  실제: 정상
예측: 암	TP = 85	FP = 10
예측: 정상	FN = 15	TN = 90

ROC-AUC가 보는 FPR은 FP / FP+PN = 10/100 = 10% TN(90)이 분모에 있어서 통제가 잘 된다.
PR(Precision_Recall)이 보는 Precision TP/TP+FP = 85/(85+10) = 89% 진음수를 사용하지 않아서 양성예측의 정확도만 본다.

희귀 사기 탐지, 거래 10,000건 (사기100건 / 정상 9900건)
사기(양성), 정상(음성)

ROC-AUC가 보는 FPR = 0/(0+9900) 사기를 하나도 못잡는데 FPR 0% 
PR이 보는 Precision & Recall Recall 0% (TP/(TP+FN) = 0/(0+100)) TN을 안 봐서 속지 않음. 사기를 하나도 못 잡는다는 게 그대로 드러남
PR 곡선은 TN을 전혀 사용하지 않는다. Precision과 Recall 모두 양성(사기)에만 집중하기 때문에, 
TN이 아무리 많아도 점수에 영향을 주지 않습니다. 그래서 불균형 데이터에서 진짜 탐지 성능이 고스란히 드러납니다.

TN = (올바른 음성) 정상 -> 정상 예측
FP = (오경보) 정상 -> 양성 예측

## Support Vector Machine(SVM)

Support Vector 지지벡터 <<
양 클래스간에 가장 가까이 있는 값들
결정경계 기준으로 양 클래스의 값들 중 결정경계와 가장 가까이 있는 값.

margin(마진)
두 support Vector간의 너비

Decision boundary(결정경계)
분류문제에서 클래스들을 구분 / 분리 하는 선

식은 wx + b

Hard margin / Soft margin

Hard margin은 outlier를 무시하지않고 최대한의 Support Vector를 찾아내서 Support vector간의 거리가(margin) 매우 좁아질 수 있다.
- 선형적으로 분리가 가능할 때는 잘 작동하지만 그러지 않은경우엔 overfitting이 발생할 수 있다.

Soft margin은 일부 outlier를 무시하고 Support Vector를 찾아서 일부 데이터가 결정경계를 침범하여 잘못 분류되는것을 허용한다. 그대신 Support vector간의 margin을 넓힐 수 있다.
- 무시 비율은 하이퍼파라미터 C로 정한다. 무시비율이 너무 커지면 underfitting문제가 발생한다.

C의 디폴트값은 1

값이 클수록 무시비율을 낮게해서 규제를 약하게하고
너무 크게 설정하면 overfitting 발생

작을 수록 무시비율을 높여 규제를 강하게 한다.
너무 작게 설정하면 underfitting 발생

overfitting이 발생하면 값을 작게,
underfitting이 발생하면 값을 크게 조정.

규제를 강하게 한다 == 모델의 복잡도를 낮춘다.
==> Overfitting일 때 진행

규제를 약하게 한다 == 모델의 복잡도를 높인다.
==> Underfitting일 때 진행

데이터를 나눌때는 보통 차원에 -1차원으로 나눈다.
ex) 2차원은 선형분리(1차원 선)
    3차원은 면분리 (2차원 면) 비선형분리

비선형 SVM

차원을 늘려 데이터에 제곱을 해서 바깥쪽데이터들이 위로 더 치우치게 만들어서 자르기 가능하게 변형

자른 후 다시 원상태의 차원형태로 복구

gamma (감마)

결정경계를 얼마나 구불구불하게 만들지 조절하는 값
Linear SVM에서는 gamma값이 영향을 주지 않는다.
오로지 Non-linear SVM에서만 사용하는 하이퍼파라미터

Underfitting시에 gamma값을 크게 == 규제를 약하게
==> 영향 반경이 좁아진다.
결정 경계가 데이터포인트 하나씩을 따라다니며 생긴다
이상치에 민감해서 overfitting될 수 있다.

Overfitting시에 gamma값을 작게 == 규제를 강하게
==> 영향 반경이 넓어진다.
각 데이터포인트가 멀리까지 영향을 미치고,
포인트들끼리 영향력이 섞여서 평균적인 경계가 그려진다.
경계가 부드럽고 단순해진다.
일반화는 좋아지지만 너무작으면 패턴자체를 못잡아서
Underfitting 위험이 높아진다.

- 각 모델들은 앞의 모델이 틀린 오차를 학습하여 전체 오차가 줄어들도록 학습.
- 얕은 트리를 많이 연결해서 전체 성능을 높이는 것이 기본 아이디어
- 분류와 회귀 둘 다 지원.
- 훈련시간이 길고 트리기반 모델의 특성상 희소한 고차원 데이터에서는 성능이 안좋음.

- 정답과 평균으로 예측한 결과간의 차이를 계산한다.

잔차를 하나씩 하나씩 더하는 이유는

Learning rate를 늘려서 overfitting을 줄이기 위해
오차를 여러번 나눠서 더해준다.

### Learning Rate 중요!!

### 경사하강법 Gradient Descent

오차가 내려가는 방향으로 파라미터를 수정해 최저점을 찾겠다는 뜻.

### 모델 파라미터 조정

- $W_{new} = W-\alpha\frac{\partial}{\partial {W}}cost(W)$
    - $W$: 파라미터, $\alpha$:학습률

- 미분 => 순간 변화율을 보기위해
- X가 바뀔때 Y는 얼마나 바뀌는가 
ex) y = f(x) / x1 = 5, y1 = 6, x2 = 6, y2 = 8
    x가 1변할때 y가 2변했다. 2/1 => 변화율 2

X 변화량 - 분모
Y 변화량 - 분자

X   Y
1   1
2   4
3   9

일때, X변화량 1 Y변화량 3 ==> 1/3 = 0.3333333 = 변화량
표현: X가 n일때의 변화율 이라고한다.

y 10 -> 5
x 1 -> 2

변화율이 음수가 나온다면 증감이 반대라는 소리
y변화 x변화 둘중에 하나가 음수여야 하기때문에
x변화율과 y변화율의 증감이 반대다 (하나가 오르면 하나가 내린다)

변화율이 양수면 증감이 동일하다.
둘다 오르거나 내린다.

* 크기: 변화율의 크기

여기서 X의 역할을 해주는건 W(파라미터) == Weight
우리가 바꿀 수 있는건 파라미터 뿐이다.

loss(y, model(x,w)) == > y, x의 데이터는 바꿀수 없기 때문에
loss가 적어지는 방향으로 w를 수정

[W(Parameter) - 변화율 * Learning Rate = 0]
변화율이 +(양수)가 나오면 줄여야하고 -(음수)가 나오면 올려야하기 때문에 가능한 공식

Learning Rate(학습률): 경사하강법에서 제일 중요 << 너무 작으면 최적점까지 도달이 오래걸리고, 
너무 크게하면 너무 멀리 가버려 최적점을 찾을 수 없다. 오히려 성능이 더 떨어지는 경우가 대다수.
돌다리 두드리듯이 한걸음 한걸음 가야하는데 이 거리를 조정해주는것이 학습률(Learning Rate)

오차가 제일 적은게 최적의 파라미터 << 최적점의 오차가 0이 나오지 않는다면 이 모델로는 오차를 더이상 줄일수 없다는 뜻.

```
import numpy as np
np.random.seed(0)

learning_rate = 0.4
# learning_rate = 0.001
# learning_rate = 10

#최적의 weight를 찾기위한 최대 반복횟수.
max_iter = 100     

#첫번째(시작) weight => random하게 잡는다.
weight =  np.random.randint(-2,3)

weight_list = [weight]  # 새로 계산된 weight들을 저장할 리스트
iter_cnt = 0 # 반복횟수를 저장할 변수

while True:
    # loss함수에 대한 미분값(기울기)을 구해서 0이면(최소지점) 반복을 멈춘다.
    if derived_loss(weight) == 0:
        break
    if iter_cnt == max_iter: # 현재 반복이 max_iter라면 멈춘다.
        break
    # 새로운 weight값을 계산
    weight = weight - learning_rate * derived_loss(weight)
    weight_list.append(weight) 
    iter_cnt += 1
```


## 선형 회귀 Linear Regression (회귀 모델)
X - Y의 관계가 선형적이다 (직선의 방정식)
X가 0일때 y가 몇인지 (y절편)

`ax+b`

EX)
키(X)   몸무게(Y)
170     80
150     55
180     90

키값을 가지고 몸무게를 예측하라.
몸무게 = W(가중치) * 키 + b(편향) / 몸무게 = (1/2) * 키 + 3 이라면 키가 0일때, 몸무게는 3kg라고 판단.

학습할때는 가장 오차가 적은 W(가중치)와 b(편향)을 찾는 것이 선형 회귀.
```
feature가 여러개면, w1 * 첫feature + w2 * 두번째 feature + ... + wn * n번째 feature + b
```
w1, w2, wn 은 각각 feature에 대한 가중치라고 생각하면 된다.

가중치는 y(예측대상)값을 올리는 가중치도 있고 떨어뜨리는 가중치도 있다.

예를 들어 집값을 예측할때 범죄율이 높다면 집값은 떨어지기에 (가중치가 y값을 낮춤)
반면에 평수는 클수록 집값이 오르기에 (가중치가 y값을 높힘)

## Ridge와 Lasso의 차이점

    - w(계수)가 너무 커져서 훈련 데이터에만 맞는 상황 발생.
### Ridge (L2 정규화)
- 계수(파라미터) 제곱의 합 - 계수를 0에 가깝게 만들지만 완전히 0으로 만들지는 않음.
    - 예를 들어 모든 선수들을 벤치로 돌려보내 약하게 제한한다, 다 남아있지만 영향력이 약해짐.
- 어떨 때 사용하는가?
    - 변수가 모두 중요하거나, 변수끼리의 상관관계가 높을 때

### Lasso (L1 정규화)
- 계수(파라미터) 절대값의 합 - 일부 계수를 정확히 0으로 만들어버림 = 변수 선택 효과
    - 예를 들어 못하는 선수는 바로 방출을 시킨다. 중요한 변수만 팀에 남기는 것.
- 어떨 때 사용하는가?
    - 변수가 많고 중요한 것이 적을 때, 자동 변수 선택이 필요할 때

- 둘다 공통적으로 우리가 강도 설정을 할 수 있다. 

```
Ridge: 계수를 골고루 줄여주는 

Lasso: 필요없는 계수는 0으로 만드는 것
```

변수들이 서로 상관관계가 높고 다 중요한 상황 → Ridge (골고루 줄여줌)

## 레이어/층(Layer)
- **Input Layer(입력층)**

    - 모델의 최종 예측결과 유닛들로 구성된 Layer
- **Hidden Layer(은닉층)**
    - Input Layer와 Output Layer사이에 존재하는 Layer.
    - 정답을 추론하기 위해 추출된 특성값들(Feature vector).
    - 이 특성값들은 한번에 찾지 않고 여러 단계에 걸쳐 찾는다.

- pytorch등 딥러닝 framework들은 Layer들 처리하는 class들을 제공한다.
- Layer들의 연결한 것을 **딥러닝 모델(Network)** 이다.
    - 딥러닝은 Layer들을 깊게 쌓은 것을 말한다.(여러 Layer들을 연결한 것)

합성 합수 미분, 연쇄 법칙

> 합성 함수란? 함수 안에 또 다른 함수가 들어있는 것

예)
h(x) = (x^2 + 1)^3 
=> 안쪽 함수    g(x) > x^2 + 1
=> 바깥쪽 함수  f(u) > u^3

> 연쇄 법칙
h'(x) = f'(g(x)) * g'(x) >> 바깥 함수 미분 * 안쪽 함수 미분

예)
- 1단계: 함수 분해
합성함수 h(x) = (x^2 + 1)^3
바깥함수 f(u) = u^3         >> u자리에 g(x)가 들어감
안쪽함수 g(x) = x^2 + 1     >> x를 받아서 변환

- 2단계: 각 함수를 따로 미분
바깥함수 f(u) = u^3 => f'(u) = 3u^2     >>> 거듭제곱 규칙 nx^n-1
안쪽함수 g(x) = x^2 + 1 => g'(x) = 2x   >>> 상수 1은 미분하면 0

- 3단계: 두 미분값을 곱한다.
h'(x) = f'(g(x)) * g'(x)
f'(g(x))대입 -> 3(x^2 + 1) >>>> u자리에 g(x) = x^2 + 1 넣기
g'(x) 대입 -> 2x

f'(g(x)) * g'(x) = 6x(x^2 + 1)^2

### Batch Gradeint Decent(배치 경사 하강법)

- 많은 계산량이 필요해서 속도가 느리다. 학습데이터가 클 경우 메모리가 부족할 수 있다.

```
1epoch = 1step의 경우 << This is batch 
ex) trainset 65000 >> 파라미터 65000 >> 예측 65000 - batch를 65000으로 할 시(1epoch, 1step)
이와 같은 경우는 학습이 굉장히 안정적이다. (이상치의 영향을 덜 받는다.)

단점은 이 전체 데이터를 한번에 메모리에 올려야한다. (연산 시간이 굉장히 길어진다.)
```

이럴 때를 위해서 나온 것이 바로 Stochastic Gradient Decent.

### 자연어 처리의 단계

#### 1. 데이터 수집 단계
- 모델 학습을 위한 데이터 확보 단계
- 수집한 자연어데이터 데이터셋을 "말뭉치/Corpus"라고 한다.
- 수집방법
    - 공개 데이터

    - 음성 파일, 통화 녹음, 동영상등의 음성으로부터 추출

#### 2. 전처리 단계
원시 데이터를 모델이 다루기 좋은 단위와 형태로 바꿔주는 것

- 텍스트 정제 및 정규화
    - 특수문자, 불필요한 공백, HTML 태그, URL, 이모티콘 등 처리
    - 오타 수정, 띄어쓰기 교정
    - 형태소 분석을 통해 단어를 형태소 단위로 분해, 이를 바탕으로 같은 의미의 단어를 통일(말했다, 말하면, 말하기) -> 말하다.

- 불용어(Stopwords, 분석에 필요없는 용어) 제거, 품사 기반 필터링을 통해 필요없는 단어 제거
- 토큰화(Tokenization)
    - 텍스트를 의미 있는 작은 단위(토큰)로 분해하는 과정

#### 3. 표현(표현 학습) 단계
- 전처리/토큰화를 마친 뒤 텍스트를 의미를 나타낼 수 있는 숫자(Vector)로 표현해야 한다.\
이 단계를 표현단계(representation) 혹은 임베딩 단계(Embedding)라고 부른다.

- 통계 기반 표현(전통 방법)
    - Bag-of-Words, TF-IDF, n-gram
    - 문서 안에서 많이 나온 단어가 그 문서의 내용을 표현하는데 중요하다. (긍/부정 비교가능) *많이 나오는 단어

- 분산 표현(distributed representation)
    - Word2Vec, GloVe, FastText
    - 딥러닝 방식, 어떤 단어의 의미를 이해하려면 주변의 단어를 보고 어떤 의미로 쓰이는지 추론하는 것(분산 표현)
- 딥러닝 기반 언어 모델 표현
    - RNN, Transformer 기반 모델(BERT, GPT)을 통한 contextualized word embedding.
    - 딥러닝 방식, 쓰인 문서 안에서 이 단어가 어떻게 쓰였는지 다시 찾아보는 방식.

이 단계의 목적은 텍스트를 벡터 공간 상의 점(또는 시퀀스)으로 나타내어, 이후 분류, 생성, 추론 모델이 사용할 수 있게 준비하는 것.

숫자로 바꾸는 단계

표현된 입력을 바탕으로 문제를 해결하는 핵심 모델이 동작하는 단계, 문제 유형에 따라 사용하는 모델이 다름
